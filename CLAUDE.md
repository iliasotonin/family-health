# Семейный кабинет здоровья — правила для агента

Ты работаешь в самостоятельно размещённом кабинете здоровья одной семьи. Приложение — хранилище
и графики; разбор архива и выводы — твоя работа. Ошибки здесь медицинские. Человеческая версия
этих правил с примерами — [docs/claude-code-workflow.md](docs/claude-code-workflow.md).

## Приватность — прежде всего

- Данные семьи **никогда** не попадают в git. Скрипты импорта с реальными значениями пиши только
  в `scripts/` или `private/` (обе в `.gitignore`). Никаких имён, дат рождения, номеров медкарт,
  значений анализов в `src/`, `prisma/`, документации.
- Не отключай pre-commit-хук и не коммить с `--no-verify` без явной просьбы человека.
- Не открывай паспорта и документы, удостоверяющие личность.
- Отдавая код на проверку другой модели, ограничь её публикуемыми файлами: база, `data/`,
  `scripts/`, `.env`, геномы — вне доступа.

## Кому принадлежит документ

- Принадлежность определяй **только по бланку**: ФИО и дата рождения на самом документе. Название
  папки и имя файла — не доказательство.
- Перед занесением сверь с членом семьи в базе. Не совпадает или не читается — спроси, не угадывай.
  Особенно для детей.
- Опечатку в бланке (неверный год при верных ФИО и клинике) отметь в записи, а не заводи нового
  человека и не выбрасывай документ.
- Противоречие между документами записывай явно. Приоритет у объективного исследования над
  анамнезом «со слов».

## Разбор архива

- Больше десятка файлов — сначала **реестр**: путь, контрольная сумма, человек, статус (`done`,
  `duplicate`, `already`, `skipped` с причиной). В конце сверь «на диске = в реестре, pending = 0».
- На macOS имена файлов в NFD: при сравнении с путями нормализуй обе стороны в NFC, иначе «й»
  и «ё» не совпадут и отметки молча не сработают.
- «Не читается» проверяй: скан без текста → рендер страниц и чтение как изображение; несколько
  бланков можно склеить в один лист; рукописное — повернуть и увеличить; `.webarchive` — это
  plist, распаковывается. Не помечай файл нечитаемым, не попробовав.
- «Пропущено» подтверждай, открыв файл, а не по названию папки.
- Разные фото одного бланка — дубликат по содержимому, даже если хэши разные.

## Значения и флаги

- Одна единица на код показателя. Приводи (гемоглобин и MCHC — в г/дл; ферритин мкг/л = нг/мл)
  и записывай в примечание исходное значение с бланка.
- Референс бланка ≠ клинический порог. Если ставишь флаг не по бланку (ферритин ниже 15 по ВОЗ при
  нижней границе бланка 10), напиши в записи, по какому критерию и почему.
- Каждая запись — с источником: лаборатория, номер бланка, дата забора.
- Дату записи бери из документа; если записываешь событие «сегодня» — сверь текущую дату, не
  проставляй задним числом.

## Выводы

- **Тенденция — только по полному ряду.** Не делай вывод по двум совпавшим точкам; сначала найди
  все замеры между ними.
- Один показатель, известный своими колебаниями (сывороточное железо, СРБ, лейкоциты), не
  становится «многолетним состоянием» от одного значения.
- **Генетика:** называй, какой аллель рисковый, и сверяй генотип с сырыми данными чипа. Соседние
  варианты одного участка могут обозначать один и тот же вариант разными буквами. Потребительские
  «BRCA»-снипы — не патогенные мутации, так и пиши.
- Когда новые данные опровергают твой прежний вывод — перепиши запись и скажи об этом прямо.
- Вывод оформляй как вопросы к врачу, не как диагноз или назначение. Дозировки лекарств не называй.

## Whoop

- Recovery, HRV, пульс покоя — ночные метрики; про дневное состояние они не говорят.
- Recovery относится к утру, нагрузка цикла — к предыдущему дню. Сравнивая, выравнивай на день.
- Непрерывного пульса и журнала в API нет — не обещай их.

## Схема базы

- Меняешь `prisma/schema.prisma` — **создавай миграцию** (`npx prisma migrate dev --name …`), не
  `prisma db push`. Иначе чистая установка по README получит неполную базу.
- Перед любой операцией, способной удалить данные (`migrate reset`, пересоздание таблиц), сделай
  копию `prisma/dev.db` и спроси человека.
